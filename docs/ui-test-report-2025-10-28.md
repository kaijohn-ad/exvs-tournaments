# 管理UIトーナメント機能 統合テストレポート (2025-10-28)

## 概要
- 対象: `/admin/events/{eventId}/tournaments` および `.../bracket`
- 環境: `http://localhost:5174`（Basic認証 `local/local`）
- テスト観点: トーナメント作成、ブラケット生成、試合結果入力の一連フロー
- 実施者: GPT-5 Codex（Cursor UI自動操作）

## シナリオと結果

### 1. 管理トップからトーナメント設定へ遷移
- イベント選択後、`トーナメント設定へ` をクリックし対象ページへ遷移できることを確認。
- 既存トーナメントがリスト表示され、操作ボタンが有効化されることを確認。

### 2. 新規トーナメント作成
- トーナメント名 `テスト新規トーナメント` を入力し作成。
- 成功フラッシュメッセージとともにリストへ即時反映されることを確認。
- エクスポートJSONに新トーナメントが含まれることを確認。

### 3. ブラケット生成
- 新規トーナメントに対し `ブラケット生成`（ランダムシード）を実行。
- 成功メッセージ表示、および `ブラケットを見る` から未開始マッチフォームが表示されることを確認。

### 4. 試合結果入力
- 決勝マッチにてスコア `1-3` を入力し、勝者 `c / d` を選択。
- `結果を保存` 実行後、成功メッセージと進行状況カードの更新を確認。
- マッチ表示が完了状態・勝者表示へ更新されることを確認。

## 追加シナリオ: 13人トーナメントの進行確認
- プレイヤー26名・ペア13組をインポートしてシード1〜13を設定。
- 新規トーナメント `13人トーナメントテスト` を作成しランダムシードでブラケット生成。
- 初期状態で上位3枠が自動完了（BYE）となり、残り10試合が未開始で表示されることを確認。
- ラウンド1の全5試合を手動で結果入力し、準々決勝以降の対戦カードが自動更新されることを確認。
- BYEを含むカードでは結果入力フォームが非表示になり「自動勝ち上がり」ラベルが表示される挙動を再確認。
- 進行状況カードの統計（完了件数・未開始件数）が結果反映ごとに正しく更新されることを確認。
- 再生成後のブラケットでもBYEが連続勝ち上がりせず、準々決勝の対戦カードが未確定の状態で保持されることを確認。
- 準々決勝→準決勝→決勝まで全試合を入力し、最終的に決勝が「完了」ステータスになることと勝者表示・進行状況（完了15/15）が更新されることを確認。

## 所感・改善アイディア
- 遷移直後にブラケット生成処理の完了を待つ間、軽微な遅延があるためローディング表示の追加を検討余地あり。
- ブラケット未生成状態から生成直後のキャッシュ差分は今回問題なし。継続的にモニタリング推奨。
