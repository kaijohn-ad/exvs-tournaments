# Boost Bracket 管理UI 仕様書 (2025-10-28 時点)

## 共通事項
- ベースURL: `http://localhost:5173/admin`
- Basic認証: `local / local`
- 画面上部には常時パンくず／戻るリンクを配置 (`← 管理トップに戻る` など)
- フォーム操作後はフラッシュメッセージで成功・失敗を通知
- JSONインポート/エクスポート機能はすべての管理画面に標準搭載
  - エクスポート欄は読み取り専用テキストエリア
  - インポート欄はJSON文字列を貼り付けて「取り込み」ボタンで実行
  - 無効データはスキップ、既存レコードは上書き

---

## 管理トップ `/admin`

### 構成
- ページタイトル: `Boost Bracket 管理トップ`
- 説明文: 管理全般の導線案内
- **イベント選択ブロック**
  - セレクトボックス: 既存イベント一覧
  - 各種管理画面へのボタン群
    - `プレイヤー管理へ`
    - `ペア管理へ`
    - `チーム管理へ`
    - `団体戦管理へ`
    - `試合ログへ`
    - `統計表示へ`
    - `トーナメント設定へ`
  - イベント未選択時は全ボタン disabled
- **新規イベント作成フォーム**
  - `イベント名`（必須）
  - `スラッグ`（任意）
  - `イベントを作成` ボタン
  - 成功時はセレクトに追加、作成完了メッセージ表示
- **登録済みイベントリスト**
  - テーブル項目: `ID / イベント名 / Slug / 作成日`

## プレイヤー管理 `/admin/events/{eventId}/entries/players`

### ヘッダ
- タイトル: `プレイヤー管理`
- `イベントID` 表示
- `← 管理トップに戻る` リンク

### フォーム: プレイヤーを追加
- `名前`（必須）
- `メモ`（任意）
- `追加` ボタン

### 登録済みプレイヤーリスト
- 件数表示 `(0)` など
- 各プレイヤー行
  - `名前`（インライン編集用 input）
  - `メモ`（インライン編集用 input）
  - `更新` / `削除` ボタン
- 操作成功時メッセージ: 例 `プレイヤー「プレイヤーA」を追加しました。`

### JSON操作
- `エクスポート` テキストエリア／ダウンロードリンク
- `インポート` テキストエリア＋ `取り込み` ボタン
- `JSONエディタを開く` ボタン（モーダルで編集想定）

## 団体戦管理 `/admin/events/{eventId}/team-battles`

### ヘッダ
- タイトル: `団体戦管理`
- `イベントID` 表示

### 団体戦作成フォーム
- `チームA` セレクト（必須）
- `チームB` セレクト（必須）
- `スロット数` セレクト（1〜5、デフォルト: 3）
- `形式` セレクト
  - `早稲田式`: 各スロットで同時に対戦。全スロット終了後に結果を確定
  - `勝ち抜き戦`: 勝者続投・敗者交代形式。いずれかのチームがスロット数分の敗戦に到達した時点で自動終了
- `タイブレーク` セレクト（形式が「勝ち抜き戦」の場合は無効化）
  - `なし`
  - `代表戦`（早稲田式のみ）
- `作成` ボタン

### 未登録時の表示
- チーム数が2未満: 作成フォームの代わりに注意文表示
  - `団体戦を作成するには、少なくとも2つのチームが必要です。`
  - `チーム管理ページ` への誘導リンク付き
- `登録済み団体戦 (0件)` / `まだ団体戦が登録されていません。`

### 登録済み団体戦リスト
- 各団体戦カード
  - タイトル: `{チームA名} vs {チームB名}`
  - 情報: `スロット数: {n}`, `形式: {早稲田式|勝ち抜き戦}`, `タイブレーク: {なし|代表戦}`
  - ステータスバッジ
  - 結果バッジ（完了時）
  - 操作ボタン: `編集` / `削除`
  - リンク: `進行管理 →` / `ラインナップ編集 →`

## 団体戦進行管理 `/admin/events/{eventId}/team-battles/{battleId}`

### ヘッダ
- タイトル: `団体戦進行管理`
- `← 団体戦一覧に戻る` リンク

### 団体戦情報カード
- タイトル: `{チームA名} vs {チームB名}`
- 情報タイル: `形式`, `スロット数`, `タイブレーク`, `結果`
- スコア表示
  - 早稲田式: `{チームA勝数} - {チームB勝数}`（勝数）
  - 勝ち抜き戦: `{チームA敗戦数} - {チームB敗戦数}`（敗戦数）

### 早稲田式の場合

#### スロット別試合結果
- 各スロット（スロット1〜スロットN）のカード
  - ラインナップ表示（チームA vs チームB）
  - 結果入力済み: 青色背景、スコア・勝者表示、`削除`ボタン
  - 未入力: 入力フォーム（スコアA/B、勝者選択、`結果を記録`ボタン）
  - ラインナップ未設定時: 注意メッセージ

#### タイブレーク（同点時）
- 代表戦の結果入力フォーム
- `タイブレーク結果を記録`ボタン

#### 確定
- 全スロット結果入力完了時: `団体戦を確定する`ボタン

### 勝ち抜き戦の場合

#### 次の対戦カード
- 現在の出場枠のラインナップ表示（チームA vs チームB）
- 試合結果入力フォーム
  - スコアA/B
  - 勝者選択
  - `結果を記録`ボタン
- 終了時: `試合終了`メッセージ
- ラインナップ未設定時: 注意メッセージ

#### 試合履歴
- これまでに行われた試合の一覧
- 各試合カード
  - 試合番号
  - スコア・勝者表示
  - 最後の試合のみ: `削除`ボタン（終了していない場合）

#### 自動終了
- いずれかのチームがスロット数分の敗戦に到達した時点で自動的に終了
- タイブレークや確定ボタンは表示されない

## E2Eテスト（Playwright）

### 概要
KOTH機能のE2EテストはPlaywrightを使用して自動化されています。テストは開発環境専用のシードAPI（`/test-utils/seed`）を使用してデータを準備します。

### 実行方法

#### ローカルでの実行
```bash
cd remix
npm run test:e2e        # ヘッドレス実行
npm run test:e2e:ui     # UIモードで実行（推奨）
npm run test:e2e:debug  # デバッグモードで実行
```

#### CIでの実行
GitHub Actionsで自動実行されます（`.github/workflows/e2e.yml`）。ブランチへのプッシュやプルリクエスト時に自動的にテストが実行されます。

### テストカバレッジ
現在のE2Eテストは以下のKOTH機能をカバーしています：

1. **KOTHバトル作成**: 形式選択、タイブレーク無効化の確認
2. **進行管理画面表示**: スコア表示、次の対戦カードの確認
3. **試合記録**: 結果入力と次の対戦カード更新の確認
4. **勝者続投・敗者交代**: 状態遷移の確認
5. **自動終了**: 最大敗戦数到達時の自動終了の確認
6. **試合削除**: 最後の試合削除と状態復元の確認
7. **ラインナップ未設定**: エラーハンドリングの確認

### テストデータシード
`/test-utils/seed` エンドポイントは開発環境専用です：
- **開発環境**: シードデータを作成可能
- **本番環境**: 403エラーを返す

シードAPIは以下のデータを作成します：
- イベント（1件）
- プレイヤー（8名）
- ペア（4組）
- チーム（2チーム）
- 団体戦（KOTH形式、3スロット）
- ラインナップ（各チームのスロット0〜2にペアを割り当て）

### テスト保守
- 新しいUI要素には `data-testid` 属性を追加してください
- テストファイル: `remix/e2e/koth.spec.ts`
- 設定ファイル: `remix/playwright.config.ts`
