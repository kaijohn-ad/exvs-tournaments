# スケジュール機能 UI統合テストケース

このドキュメントには、スケジュール機能のブラウザーから実行するUI統合テストのテストケースを記載します。

## テスト環境

- **サーバーURL**: http://localhost:5174（開発サーバー）
- **実行方法**: ブラウザーから手動実行、または自動化ツールを使用
- **更新日**: 2025-01-27

## テストケース一覧

### TC-SCHEDULE-001: 管理画面スケジュールページの表示

**前提条件**: 
- 開発サーバーが起動している（http://localhost:5174）
- イベントが作成されている

**テスト手順**:
1. ブラウザーで管理トップページ `http://localhost:5174/admin` にアクセス
2. イベントを選択または作成
3. イベント詳細ページから「スケジュール」リンクをクリック
4. スケジュールページ `http://localhost:5174/admin/events/{eventId}/schedule` にアクセス

**期待結果**:
- スケジュールページが正常に表示される
- 「このイベントの試合を追加順に表示しています。」という説明文が表示される
- 未開始・進行中の試合が追加順（キュー形式）で表示される
- 完了した試合は表示されない

**確認項目**:
- [ ] ページタイトルが正しく表示される
- [ ] 説明文が「追加順に表示」となっている
- [ ] 試合にキュー番号（#1, #2, ...）が表示される
- [ ] 日程表示が削除されている
- [ ] 完了した試合が表示されない

---

### TC-SCHEDULE-003: 未開始のブラケットマッチが表示される

**前提条件**: 
- イベントが作成されている
- トーナメントが作成されている
- ブラケットが生成されている（未開始の試合がある）

**テスト手順**:
1. ブラウザーでスケジュールページにアクセス
2. 未開始のブラケットマッチが表示されることを確認

**期待結果**:
- 未開始（`pending`）のブラケットマッチがスケジュールに表示される
- 進行中（`in_progress`）のブラケットマッチも表示される
- BYEの試合も正しく表示される

**確認項目**:
- [ ] 未開始のブラケットマッチが表示される
- [ ] 進行中のブラケットマッチが表示される
- [ ] BYEが正しく表示される（「BYE」と表示される）

---

### TC-SCHEDULE-004: 追加順（キュー形式）で表示される

**前提条件**: 
- 複数の未開始試合が存在する

**テスト手順**:
1. ブラウザーでスケジュールページにアクセス
2. 試合の順序を確認

**期待結果**:
- 試合が追加順（古い順）で表示される
- キューの番号（#1, #2, #3, ...）が正しく連番で表示される
- 最初に追加された試合が#1として表示される

**確認項目**:
- [ ] 試合が追加順（古い順）で表示される
- [ ] キュー番号が連番で表示される
- [ ] 最初に追加された試合が#1として表示される

---

### TC-SCHEDULE-005: 完了した試合が除外される

**前提条件**: 
- 完了した試合と未開始の試合が存在する

**テスト手順**:
1. ブラウザーでスケジュールページにアクセス
2. 完了した試合が表示されないことを確認

**期待結果**:
- 完了（`completed`）した試合はスケジュールに表示されない
- 未開始・進行中の試合のみが表示される

**確認項目**:
- [ ] 完了した試合が表示されない
- [ ] 未開始・進行中の試合のみが表示される
