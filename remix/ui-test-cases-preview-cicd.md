# PRプレビューCI/CD機能 テストケース

このドキュメントには、PRプレビューCI/CD機能についてのテストケースを記載します。

## テスト環境

- **ローカルサーバーURL**: http://localhost:5173（開発サーバー）
- **実行方法**: ブラウザーから手動実行、または自動化ツールを使用
- **更新日**: 2025-01-XX

## 注意事項

**重要**: PRプレビューCI/CD機能自体はGitHub ActionsとCloudflare Pagesの統合機能です。以下のテストケースのうち、実際のCI/CD動作（PR作成時の自動デプロイ、PRコメント投稿など）は、実際のGitHubリポジトリでPRを作成しないとテストできません。

ローカルブラウザーでテスト可能なのは、**アプリケーションの基本動作**のみです。

---

## テストケース一覧

### TC-PR-001: アプリケーションの基本動作確認（プレビュー環境のシミュレーション）

**目的**: PRプレビュー環境で使用されるアプリケーションが正常に動作することを確認

**前提条件**: 
- 開発サーバーが起動している（http://localhost:5173）
- D1データベース接続が有効（またはメモリストアが動作）

**テスト手順**:
1. ブラウザーで `http://localhost:5173/` にアクセス
2. ホームページが正常に表示されることを確認
3. D1統合メッセージが表示されることを確認
4. `/events` ページにアクセス
5. `/admin` ページにアクセス

**期待結果**:
- すべてのページが正常に表示される
- D1統合が有効であることが表示される
- データベース接続エラーが発生しない

**確認項目**:
- [ ] ホームページが正常に表示される
- [ ] D1統合メッセージが表示される
- [ ] イベント一覧ページが正常に表示される
- [ ] 管理ページが正常に表示される
- [ ] コンソールエラーが発生しない

**ステータス**: ⏳ 未実行

---

### TC-PR-002: データベース接続の環境別動作確認

**目的**: プレビュー環境とプロダクション環境で異なるデータベースを使用する設定が正しく動作することを確認

**前提条件**: 
- 開発サーバーが起動している
- 環境変数 `ENVIRONMENT_STAGE` の動作を確認したい

**テスト手順**:
1. ブラウザーで `http://localhost:5173/` にアクセス
2. 開発者ツールのコンソールを開く
3. サーバーログまたはクライアントログで環境ステージ情報を確認

**期待結果**:
- 開発環境では適切な環境ステージが設定されている
- データベース接続ログが出力される（本番環境と同じ形式）

**確認項目**:
- [ ] 環境ステージ情報がログに出力される
- [ ] データベース接続状況がログに出力される
- [ ] 環境に応じたデータベースが使用される（開発環境ではメモリストアまたは開発用D1）

**ステータス**: ⏳ 未実行

**注意**: 実際のプレビュー環境とプロダクション環境での動作確認は、Cloudflare Pagesで実際にデプロイする必要があります。

### TC-PR-003: GitHub Actionsワークフローの設定確認

**目的**: PRプレビューCI/CD機能のワークフロー設定が正しいことを確認

**前提条件**: 
- GitHubリポジトリへのアクセス権限がある

**テスト手順**:
1. `.github/workflows/deploy.yml` を確認
2. 以下の設定が存在することを確認：
   - `pull_request` トリガー
   - `concurrency` 設定
   - プレビューURL取得ステップ
   - PRコメント投稿ステップ

**期待結果**:
- すべての設定が正しく記述されている
- YAML構文エラーがない

**確認項目**:
- [ ] `pull_request` トリガーが設定されている
- [ ] `concurrency` 設定が存在する
- [ ] プレビューURL取得ステップが存在する
- [ ] PRコメント投稿ステップが存在する
- [ ] YAML構文エラーがない

**ステータス**: ✅ 確認済み（実装時に確認）

### TC-PR-004: 実際のPRプレビュー動作確認（手動テスト）

**目的**: 実際のGitHub PRでプレビュー環境がデプロイされ、PRにコメントが投稿されることを確認

**前提条件**: 
- GitHubリポジトリへのpush権限がある
- テスト用のブランチを作成できる

**テスト手順**:
1. 新しいブランチを作成: `git checkout -b test/preview-deployment`
2. 何かしらの変更をコミット（例: READMEの更新）
3. ブランチをpush: `git push origin test/preview-deployment`
4. GitHubでPRを作成
5. GitHub Actionsの実行状況を確認
6. デプロイ完了後、PRにコメントが投稿されることを確認
7. プレビューURLにアクセスして動作確認

**期待結果**:
- PR作成時にワークフローが自動実行される
- デプロイが成功する
- PRにプレビューURLがコメントされる
- プレビュー環境でアプリケーションが正常に動作する
- プレビュー環境は開発用D1データベース（`exvs-tournaments-dev`）を使用する

**確認項目**:
- [ ] PR作成時にワークフローが実行される
- [ ] デプロイが成功する
- [ ] PRにプレビューURLがコメントされる
- [ ] プレビューURLにアクセスできる
- [ ] プレビュー環境でアプリケーションが正常に動作する
- [ ] プレビュー環境でデータベース操作が正常に動作する

**ステータス**: ⏳ 未実行（要手動テスト）

**注意**: このテストは実際のGitHubリポジトリとCloudflare Pagesで実行する必要があります。

### TC-PR-005: Concurrency設定の動作確認

**目的**: 同じブランチでの並列実行が最新のもののみ実行され、古い実行がキャンセルされることを確認

**前提条件**: 
- GitHubリポジトリへのpush権限がある

**テスト手順**:
1. 新しいブランチを作成: `git checkout -b test/concurrency`
2. 変更をコミットしてpush: `git push origin test/concurrency`
3. すぐに別の変更をコミットしてpush（2回目のpush）
4. GitHub Actionsで複数のワークフローが実行されることを確認
5. 最新のワークフローのみが実行され、古いものがキャンセルされることを確認

**期待結果**:
- 2つのワークフローが開始される
- 古いワークフローが自動的にキャンセルされる
- 最新のワークフローのみが完了する

**確認項目**:
- [ ] 複数のワークフローが開始される
- [ ] 古いワークフローがキャンセルされる
- [ ] 最新のワークフローのみが完了する

**ステータス**: ⏳ 未実行（要手動テスト）

### TC-PR-006: 本番環境へのデプロイ確認（masterブランチ）

**目的**: masterブランチへのpushで本番環境にデプロイされることを確認

**前提条件**: 
- GitHubリポジトリのmasterブランチへのpush権限がある
- 本番環境へのデプロイが許可されている

**テスト手順**:
1. masterブランチに切り替え: `git checkout master`
2. 何かしらの変更をコミット（小さな変更、例: ドキュメント更新）
3. masterブランチにpush: `git push origin master`
4. GitHub Actionsの実行状況を確認
5. デプロイ完了後、本番環境で動作確認

**期待結果**:
- masterブランチへのpushでワークフローが実行される
- デプロイが成功する
- 本番環境でアプリケーションが正常に動作する
- 本番環境は本番用D1データベース（`exvs-tournaments-db`）を使用する

**確認項目**:
- [ ] masterブランチへのpushでワークフローが実行される
- [ ] デプロイが成功する
- [ ] 本番環境でアプリケーションが正常に動作する
- [ ] 本番環境でデータベース操作が正常に動作する

**ステータス**: ⏳ 未実行（要手動テスト）

**注意**: 本番環境へのデプロイは慎重に行ってください。
